# trez63.com

One small single-page app a day, built by AI (Claude, ChatGPT, Gemini, Grok, Muse). Served by GitHub Pages at https://trez63.com.

## Layout

| Path | What |
|---|---|
| `apps/<slug>.html` | The apps, one self-contained file each. Always the latest version; history is in git. |
| `thumbs/<slug>.webp` | 640×400 screenshot of each app, retaken whenever the app changes. |
| `catalog.json` | Source of truth for the index: title, engine, description, versions, dates, thumbnail recipe. |
| `index.html`, `p/<slug>.html`, `feed.xml` | Generated by `scripts/build_index.py` — do not edit by hand. `p/` pages wrap each app in an iframe with a title bar and carry the social (OG) meta. |
| `previews/<slug>.webm` | ~4s silent hover preview, recorded alongside the thumbnail. |
| `scripts/publish.py` | Daily publisher. Ingests a folder of HTML files, detects new/changed apps by hash, screenshots them, updates the catalog, rebuilds the index. |

## Daily flow

1. The AI engines drop their finished app into the connected source folder (filename convention: `<name>-<engine>.html`; a re-saved file with the same name is treated as a new version).
2. A scheduled Claude task stages that folder, runs `python3 scripts/publish.py --source <folder> --dates <list>`, writes a one-line description for anything new, and pushes to `main`.
3. Apps are dated by the day they were made, not the day they were published: `--dates` takes a list of `<date>|<file name>` lines produced on the computer that holds the folder (staged copies lose their mtime), and a `Daily Build YYYY-MM-DD` in an app's `<title>` counts too. A catalog date later than the file's is pulled back; nothing is ever moved later.
4. GitHub Pages rebuilds within a minute.

Each app has an optional `category` in the catalog (tool, art, game, audio, sim, image, finance, dev, focus, text, edu) that drives the filter chips.

Only `*.html` is ever published. Save files (`*.json`), shortcuts and anything else in the source folder are ignored.

## Privacy gate

`scripts/privacy_check.py` scans for emails, phone numbers, API keys/tokens, AWS account IDs, private IPs, home-directory paths, street addresses, SSN/card shapes, and (optionally, `--terms FILE`) a private word list kept outside the repo. `publish.py` runs it on every incoming file and refuses to copy anything with findings, then sweeps `apps/`, `catalog.json`, `index.html` and `README.md` before exiting. Run it by hand on anything else before committing: `python3 scripts/privacy_check.py --terms <file> <paths>`. `scripts/privacy_allow.txt` lists exact strings that are known fakes (the 4242 test card, AWS's documentation key, an app's own demo data) so a redaction demo can ship without weakening the rules; the private word list is never allowlisted.

## Likes

Each card and play page has a like button. Counts live in [Abacus](https://abacus.jasoncameron.dev), a free third-party counter service: namespace `trez63.com`, one counter per app slug, incremented straight from the visitor's browser. No account and no backend of ours. A browser remembers what it liked in `localStorage`, so one click per app per browser; that is a courtesy limit, not protection against a determined person.

Pages show the count stored in `catalog.json` (`likes`) and refresh what is on screen from the service. The daily task snapshots the counts with `scripts/fetch_likes.js` (run in a browser tab) and `scripts/apply_likes.py`, which never lowers a stored number, so the catalog doubles as the backup if the service resets or goes away. "Most liked" is the default view. It opens on the stored counts and refreshes the cards on screen; clicking the button sorts on the stored counts at once, then fetches the live count for every app (the service has no bulk call, so this is paced under its 30-requests-per-10s limit and takes about half a minute for ~80 apps) and re-orders as they arrive.

## Browsing

The index groups apps under the day they were first published and shows 24 at a time (a page always finishes the day it ends on); "Show more" adds the next 24. "Most liked" is a flat list, paged the same way. "Surprise me" opens a random app from whatever the current search and filters match. Each play page has previous / next links (same order as the index, wrapping at the ends) and its own "Surprise me".

## Editor's choice

`publish.py --picks FILE` reads a plain text file kept outside the repo: one app per line (title, slug or file name; `#` starts a comment). The file is the whole truth: an app is `featured` in `catalog.json` only while a line names it. Featured apps get a row at the top of the index (newest eight), a tag on their card and a filter. With no featured apps none of that is rendered.

## Visit counts

Two layers. Google Analytics (GA4, a property used only by this site; the tag is in `build_index.py`) gives referrers, countries and devices, but ad blockers hide part of the audience from it. Underneath, as an unblocked baseline with no cookies, each page adds one to a few anonymous counters on the same counter service the like buttons use (keys `stat-v-DAY` page views, `stat-u-DAY` browsers seen that day, `stat-r-DAY` of those arriving from Reddit, `stat-o-DAY` app pages opened, `stat-open-<slug>` opens per app; days are Pacific time). `stats.html` (generated, unlinked, noindex) shows the last 7 days. Opening any page once with `?notrack=1` stops that browser being counted.

## Experiments

Two engagement ideas were tried in November 2026, each on half of all browsers chosen at random (traffic comes in spikes, so before/after numbers mean nothing). Neither helped and both were removed. No experiment code is left in the pages.

- **Experiment 1 (2026-11-17 to 11-18): intro strip on app pages. No improvement.** About four in five visitors land on an app page and never open the main page, so one group got a strip under the app page's top bar: what the site is, the same day's apps from the other models, and a link to all apps. 202 visitors without it, 181 with: app opens per visitor 3.11 vs 2.70, main page views 0.42 vs 0.45, likes 0.03 vs 0.02. 16% clicked the strip, but those clicks replaced "Next app" clicks. Counter keys `stat-ab1-*`.
- **Experiment 2 (2026-11-18 to 11-23): like nudge. No improvement.** After 25 seconds on an app without a like, the like button turned yellow and read "Like it?". 203 visitors without it, 177 with: likes 4 vs 2 (119 nudges shown), app opens per visitor 3.97 vs 2.86, main page views 0.46 vs 0.46. Counter keys `stat-ab2-*`.

What the two tests agree on: visitors open three to four apps and leave whatever the page offers, and about 2 in 100 like something. Page changes did not move either number. By 2026-11-22 the site was at about 40 visitors a day, where a test needs months to show anything, so further experiments wait for traffic.
