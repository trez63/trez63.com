Your model, in words.

Follow the permission.

  1. Choose a role, then an ability. D means a direct grant exists. I means access is inherited, with no direct grant. A dash means there is no access.
  2. Trace the sources. Routes point from the selected role toward a role that grants the ability directly. One shortest route is shown per granting role. Multiple routes do not multiply access.
  3. Explore a change. Remove a direct grant after reading its local impact preview. Inherited access can remain. Undo restores the last model change.
  4. Build your own model. Add or edit roles and abilities. Inheritance loops are rejected. Removing a role also removes references to it; removing an ability clears its direct grants.
  5. Save and reuse. Save downloads a versioned JSON file containing the entire model and view settings. Open validates the file before asking to replace current work.

This is an allow-only union model. It does not model deny rules, conditions, resource scope, user membership, or any system’s enforcement rules. The example is fictional. A report explains this model; it is not a security audit.

Up to 12 roles and 32 abilities. No custom keyboard shortcuts; native Tab, Enter, Space, and dialog Escape keep their usual behavior. Typing a new model name clears the app’s one-step Undo; native text undo remains available.
