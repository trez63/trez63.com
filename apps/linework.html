    The final list.

    A recipe you can read.

    1. Paste your source. Every newline separates a row. Windows and old Mac newlines become line feeds. A trailing newline creates a blank row; Remove blank rows can discard it. Empty source means zero rows.
    2. Arrange the steps. Add up to eight. Earlier / Later changes order. Disabled steps pass their input through, including incomplete drafts.
    3. Inspect each stage. Select Source or any step. The ledger shows up to 100 rows per page; pagination never truncates exports. Blank rows are marked for readability.
    4. Take the final output. Copy final and Export final always use the end of the complete recipe. An error blocks both, even while you inspect an earlier successful stage.
    5. Keep the recipe. Save includes source, ordered steps, settings, and inspected stage. Open validates a saved file before replacing work. Typing clears the app’s one-step Undo; native text undo remains available.

    Replace uses exact, case-sensitive, non-overlapping literal matches. No regex or replacement tokens are interpreted. Dedupe keeps the first occurrence. Ignore case uses ordinary Unicode lowercase matching. Sort compares text by JavaScript code-unit order, not numeric or language-specific collation; ties retain their input order.

    Limits: 100,000 source characters, 5,000 rows, eight steps, and 250,000 characters at every output stage. Rule text stays on one line. Oversized pasted source remains visible but cannot be processed or saved until reduced; no output is silently shortened. No custom keyboard shortcuts; native typing, Tab, Enter, Space, and dialog Escape keep their usual behavior.
